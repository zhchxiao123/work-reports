01

定位与职责

OCE 是管理 Agent 的平台，OCC 是控制面。部署 Agent 与处理用户消息是两条不同链路。

控制面

管理 Namespace、Agent、Configuration、Secret、身份与部署状态。不是每轮模型推理的执行器。

数据面

部署后的 gateway 接消息，Harness 运行模型与工具。每个部署 Agent 有自己的 gateway。

部署边界

默认 Compose preview 不能部署 Agent；当前快速路径选择 Kubernetes。名称中的 Enterprise 不能替代运行验收。

02

资源与多租户

Namespace 是平台资源作用域；AgentRevision 冻结一次部署的配置与执行设置。

Agent → AgentRevision

Agent 是持久定义，创建不启动进程；部署产生不可变 Revision，worker 准备并激活。改配置后必须再次部署。

Configuration 与 Secret

原生配置可复用，Secret 单独保存，接口返回 metadata 而非秘密值。配置绑定在运行侧解析。

身份模型

Principal、ServicePrincipal、Role、AccessBinding 与 Restriction 分别建模。Agent 使用自己的稳定身份，不继承创建者权限。

官方依据：产品对象与租户概念

03

部署时序与恢复

API 接受的是部署意图，worker 处理异步基础设施动作；租约恢复针对控制面工作，不等于会话任务自动续跑。

Controller 独立于 HTTP API。文档描述 worker graceful shutdown 后工作可由其他 worker 在租约过期后恢复；这属于部署 reconcile。Kubernetes gateway 当前单副本 Recreate，更换版本可能中断服务，并非无缝高可用。

官方依据：Controller reconciliation；blob f32742ec3d2a8875f643720b07cfda959f49e861

04

Gateway 与 Harness 分离

Embedded OpenClaw 与 Dedicated Codex 的运行拓扑不同；分离 gateway 和 Harness 也不自动分离 Harness 与工具执行。

Supported

文档列出 embedded OpenClaw（Kubernetes / SSH）与 dedicated Codex（Kubernetes）。

实验路径

Dedicated OpenClaw 需要 full-facet sandbox provisioning；stock OpenShell 存在上游 blocker，不能视为支持的生产路径。

Credential 路径

模型凭据与 gateway transport 身份分开；credential_source 需要特定 gateway + Sandbox 组合，不能直接套到任意 Driver。

05

和 DSH 多实例的关联

最值得参考的是资源、身份与部署的控制面分层，而不是把它当现成 DSH 请求负载均衡器。

借鉴资源契约

把 DSH 实例、配置 revision、部署意图与运行状态分开；避免把用户 binding 与基础设施身份混成一个对象。

借鉴 worker claim

从当前本地 SQLite 轮询改为共享持久工作、原子领取、租约和失效恢复。但运行中的 DSH ctx 仍需 owner 与 fencing。

需要自行适配

DSH 不在已读支持矩阵里。接入 Compute / Harness 协议、会话路由、取消和恢复均需开发；CubeSandbox 也不能直接当 bundled Sandbox Driver。

OCC API 多副本 ≠ 同一 Agent Harness 多副本 ≠ 同一 DSH binding 安全并发。控制面可扩展与数据面的会话归属是不同问题。
06

验证路线与风险

先做资源与部署实验，再看能否复用代码；不要先替换当前已验证环境。

实验

独立集群创建 Namespace / Agent，观察 Revision、队列与 readiness；故障注入只针对 controller claim，不混入模型效果。

审查

检查 IAM 范围、Secret 投影、Driver 信任配置、旧版本退出与新版本激活顺序。对接 DSH 时补充双 owner 防护。

证据边界

本次读取 README、concepts、controller、execution 和 driver 文档；没有部署、运行 CI 或源码全面审计。原生支持以文档组合为限。
