01

核心：托管 Agent 的运行系统

它不只是模型 API：你定义能力与环境、发送事件，平台负责运行循环与上下文优化。模型、编排、执行和状态是不同职责。

你负责

产品 UI、用户权限、业务授权、任务输入、产物验收，以及选择自定义工具与执行环境。

平台负责

可配置的预构建 Harness、模型循环、工具路由和服务端会话；内建提示缓存与上下文压缩。

不要混淆

“托管 Harness”不等于你能任意上传一个 Harness 实现；公开工程设计的抽象范围与当前 API 的配置面不同。

02

四个 API 对象怎样协作

Agent 定义“谁来做、能做什么”；Environment 定义“在哪执行”；Session 承载任务；Events 是交互与观察接口。

Agent 版本

配置可复用、可版本化；改变配置产生新版本，可提供 version 做乐观并发检查。新版本不等于自动改写所有运行中的 Session。

环境不是实例

云 Environment 可配置软件包与网络；多个 Session 共享配置，各 Session 获得独立 Linux 容器。环境 ID 不能直接理解为共享磁盘或同一 VM。

Session 与事件

创建后发送 user.message 推进工作；应用订阅事件看输出和状态。会话历史保存于服务端，断线并不等于丢失历史。

来源：Agent 配置与版本

来源：云 Environment 与隔离沙箱

Environment 是配置，Session 是任务，Sandbox 是执行实例。 云端每个 Session 有独立沙箱的归属；当前文档写明，沙箱在创建会话时开始后台准备，推理不必等它；空闲时做检查点，状态最多保留 30 天。“一会话一沙箱”不等于“每条消息新建沙箱”。

复用 Environment

复用的是环境配置和可缓存的依赖，不是同一个文件系统。Session 1 和 Session 2 在云模式下仍各有隔离沙箱。

复用 Session

同一 Session 可以接收多条消息继续任务；一次工具调用不是一次新会话。无需每发一条消息就创建新沙箱。

与我们的 B 对照

当前 DSH 按空间 × 用户 × 工作区绑定 B，同一绑定的多个会话复用 B。Claude 云端的隔离粒度是 Session；自托管 worker 的隔离要另外核对。

03

一次任务的端到端链路

API 层看见的是事件驱动任务，内部则是模型 → 工具 → 结果 → 模型的循环。下面是职责时序示意，不是未公开调度器的实现图。

实时与历史配合

新 SSE 只发送连接后的事件。重连先开流，再分页取历史，以事件 ID 去重后追踪实时流，避免连接间隙漏事件。

完整事件与预览

agent.message 通常在对应模型请求结束后产生；想在生成中展示文本要用 event deltas，不能把所有 SSE 事件都当 token。

转向和中断

可发送后续用户事件引导任务，或 interrupt。客户端必须处理待确认、工具结果与错误等事件，而不只是聊天文本。

来源：事件、重连与流式交互

04

两种执行方式：云沙箱与自托管 worker

执行地点可以变，托管 Agent 编排的职责保持在平台。不能把 self-hosted 理解成整套 Claude 运行栈部署到你的服务器。

云沙箱

Environment 指定软件包与网络配置，Session 使用隔离实例；依赖可在相同环境配置之间缓存。

自托管

Environment 是队列，worker 领取工作并执行工具，传回结果。官方预构建 worker 需要 Linux /bin/bash，仅需出站 HTTPS。

数据边界

本地文件、进程与网络流量在你的基础设施，但工具输入输出仍传到 Anthropic，skills 与 memory stores 也有平台侧存储。不能据此承诺“所有数据不出网”。

来源：自托管队列、worker 与数据流

接 CubeSandbox 的研究路径：把 worker 放到受控 B 环境，或实现兼容 worker 的执行适配。仅有 SSH 入口不足以完成接入；队列领取、执行隔离、授权和状态同步需要另行验证。此项尚未实现。
05

工具、权限、Skill 与凭据各自做什么

工具提供动作接口，Skill 提供使用知识；权限决定动作何时能执行，凭据代理决定秘密如何使用。

内建工具

Bash、read / write / edit / glob / grep，以及 web 搜索与抓取；可按工具启用、禁用与配置。超大工具输出会落文件并返回预览与路径。

自定义工具

由你的应用执行并回传结果；业务权限与副作用由应用控制，不受服务端 permission_policy 自动覆盖。

MCP 与 Skill

MCP 接外部工具服务；Skill 在 Agent 配置中提供领域知识并按需展开。两者不是相同资源，也不能替代身份授权。

来源：工具执行职责

来源：Agent 的 Skills 与 MCP 配置

always_allow

直接执行。内建 agent toolset 默认采用此策略；不是默认每条都经过自动风险审查。

always_ask

等待应用确认。MCP toolset 默认采用此策略；适合必须人工检查的动作。

auto

服务端评估后允许、拒绝或要求确认。自动允许可能直接产生副作用，不等于人工审阅。

来源：权限策略与默认值

凭据如何与工具路径分离？

工程文章描述：凭据位于沙箱外的 vault / 资源授权路径；MCP 代理按 Session 取得相应凭据后调用服务。API 文档允许在 Session 关联 vault，MCP 凭据按服务 URL 匹配。模型与生成代码不应直接处理原始 Token。

这说明公开设计目标；具体部署拓扑和所有失败路径没有公开，不能从图中推断每种 Secret 都绝不可能泄露。

06

恢复的关键：历史不能只存在进程里

工程文章公开的核心设计是让会话记录、Harness 和工具环境可分别替换。持久事件历史与模型当前可见上下文不是同一份东西。

工程文章用 wake / getSession / emitEvent / getEvents 等接口解释职责。这里作为设计示意，不把它们写成你可直接调用的公开 SDK 方法。恢复也不等于任意外部副作用 exactly-once。

来源：Anthropic 工程文章 · 2026-04-08

idle

等待输入或确认；完成一轮通常回到 idle，但不代表所有 workflow run 都结束。

running / rescheduling

正在执行 / 暂态故障后的自动重调度。应用仍要读取错误和状态事件。

terminated

不可恢复错误或归档后结束；不能用它作为普通任务完成信号。

来源：Session 状态

07

多 Agent 与工作流：观察粒度要继续拆分

不能只看主会话最后一条消息。跨线程协作与 workflow run 有各自的进度、状态和结果。

Subagents

Agent 配置可开启委派与动态 workflows。研究时需要区分主 Session、执行线程与子任务，不把“一次委派”直接等同于一台独立 VM。

Workflow runs

可追踪创建、运行、暂停、阶段开始结束与最终结果。Session idle 时 run 仍可能开放；工作完成要检查 run 是否已结束。

结束不等于质量通过

run 的 completed 说明工作流结束，不保证全部线程工作成功或业务验收通过；仍需检查线程事件与产物。

来源：多 Agent 编排

来源：Run 事件与完成判定

08

对照 DSH + CubeSandbox：能借鉴什么

相似的是编排与执行分离；差异在资源粒度、状态外置、API 契约与治理。下面是基于已核对项目代码的对照，不是兼容性承诺。

维度Managed Agents当前项目
编排托管 Harness 与上下文优化A 内多 DSH ctx，宿主进程常驻
归属与粒度Agent / Environment 可复用；云 Session 独立沙箱binding = 空间 × 用户 × 工作区，多会话复用 B
事件与恢复服务端事件历史 + 流与重连契约原生会话持久化 + 平台操作状态，尚非同等统一事件控制面
执行环境托管沙箱或自托管 workerCube PVM + 生命周期 SSH 适配器
文件恢复由对应环境与 sandbox 契约管理，不推断为 Firecracker 快照B 的 POSIX 文件检查点，非进程内存恢复
凭据与治理vault / MCP 代理 / 权限策略绑定 home 凭据 + 平台 ACL，尚非同等 vault 体系

优先研究 ①

独立 Session 事件账本、断线重连与完成判定；把 A 内会话存储与跨进程恢复契约进一步分离。

优先研究 ②

验证 Cube B 与官方 self-hosted worker 的兼容性；先做单 Session 工具调用，不先假设多租户复用可直接套用。

优先研究 ③

凭据外置、动作权限、幂等与结果未知的处理；用真实业务产物和故障注入验证恢复质量。
