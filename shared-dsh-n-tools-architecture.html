01

一个 A，按需运行的 N 个 B

“一个 DSH”指一个常驻宿主进程；每个绑定仍加载独立的官方 DSH 上下文。物理运行中的 B 数量可以是 0 到 N。

点击图中节点查看说明。A 是进程内逻辑隔离，B 是 PVM 执行边界。
02

用户如何分开

绑定键是「空间 × 用户 × 工作区」，不是「每个会话一个 B」。同一绑定的多个会话复用 B；同一共享工作区中的不同用户仍有不同的 B 和私有状态。

原生页面与配置

复用 DSH 官方 Web、模型设置和凭据接口。没有新增“私人配置”面板。每个上下文使用独立配置与会话存储；凭据接口只返回配置状态，不返回 Key。

入口与权限

/dsh/<workspaceId>/ 由登录 Cookie 确定用户。HTTP 与 WebSocket 校验成员关系、角色和来源；退出或撤权会关闭已有连接。

共享 A 的边界

用户上下文共享 Node 进程、依赖和故障域。限制宿主机终端、任意插件安装和代码表达式配置；不能把它视为用户之间的操作系统隔离。

03

从问答到工具执行

纯文本问答不需要 B。文件浏览、读写、命令执行等文件系统或工具活动，才进入工具生命周期。

模型请求与对话编排在 A；B 执行工具。已提交的有副作用 RPC 在连接丢失后不会自动重放，结果未知时需要核对。
04

B 的生命周期

回收的是工具计算环境，持久化数据保留。A 持续运行，下一次工具调用等待 B 就绪后继续。

避免执行中误回收

适配器每 5 秒检查活动；在途 RPC、流、进程和终端等活跃资源持续续租。控制器在最后租约释放约 5 秒后才考虑回收。

按需启动，不等于零延迟

并发 ensure 合并，并按绑定加锁。恢复已有暂停环境或从模板重建；启动与文件恢复有等待时间，尚未承诺启动 SLA。

失败时保留证据

恢复未完成、检查点缺失或校验失败时拒绝空目录替代，进入显式恢复流程。旧 SSH 连接和进程句柄不跨重建继续使用。

05

文件持久化与重建

工作目录在 B 的本地 POSIX 文件系统上运行，避免直接在 S3/FUSE 上依赖硬链接与原子写语义。持久卷存放可校验的检查点。

持久化的是文件状态，不是整个进程快照。 工具修改后，在下一次模型请求前执行检查点；平台直接写入在返回成功前检查点，暂停前再检查点。未完成的后台副作用、进程内存和外部服务事务不在恢复保证内。

重建与资源模型

后续仍在 220 重建：保留镜像缓存，不需要传本地镜像；按恢复手册恢复服务、A 状态与 B 的卷和检查点。

需要一起保护的状态

A：平台数据库、原生配置、凭据和会话。B：绑定信息、卷、检查点和恢复账本。Cube：MinIO 数据、模板和 PVM 基础文件。

恢复入口

先读仓库 recovery/RUNBOOK.md 与 platform/RUNBOOK.md。保留 /opt/dsh-cube-verify、/data/cubelet 与内核等基础数据；新建运行实例，使用保存的映射恢复。

资源节省来自 B

总资源 ≈ Cube 基础开销 + 常驻 A + 当前活跃 B 的总和。空闲 B 回收后节省计算资源，卷与检查点仍占存储；本报告不提供未经测量的容量数值。
