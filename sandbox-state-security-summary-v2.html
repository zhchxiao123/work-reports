快照、克隆与回滚：Agent 沙箱的新安全问题

沙箱能休眠、能快照、能克隆之后，状态就从运行时的临时产物变成了需要长期保管的资产。清理也从“删一个容器”变成了“删一串副本”。安全边界从进程扩展到了状态。

一句话：休眠和快照解决了成本与续跑，但凭证、登录态和上下文也跟着落盘了。这些状态要像资产一样管理：谁能读、谁能恢复、保留多久、谁来删。

01Agent 的状态有六类，处理方式不同

状态包括能否重建处理方式
模型上下文对话历史、工具返回、计划可以，费用高放在应用侧
文件系统工作目录、生成物、修改过的配置可以，结果未必一致持久化
运行环境依赖、编译产物、环境变量可以，版本未必一致镜像或模板
会话凭据Cookie、OAuth 令牌、SSH 密钥、云凭证不能，只能轮换重点保护
进程内存堆、栈、文件描述符、数据库连接不能，只能快照快照，且要加密
外部副作用已发的消息、已下的订单不可撤销记录并补偿

02三个后果

快照成为资产

谁能恢复，谁就有全部权限

快照里可能有解密后的密钥、会话令牌和上下文。它是独立资源，权限容易配宽；任务结束、沙箱删除后，快照可能还在，还可能被复制到别的区域。

克隆放大风险

一份状态变成 N 份

凭证和被注入的恶意指令都会跟着复制。业务要求各实例状态一致，安全要求凭证、网络身份和审计标识各不相同。出事后也很难判断污染从哪来。

回滚带回旧事实

恢复的状态可能从未真实存在过

已撤销的令牌重新有效，被拒绝的审批回到待批准，被隔离的文件又出现了。审计时间线也会断裂。

论文实证：正确的回滚不等于安全的恢复

arXiv 2608.29381，已核对摘要

论文 Safe to Resume? 在 Hermes、Cline、LangGraph 上构造了三类端到端攻击：绕过恶意代码验证、未授权转发邮件、重复支付，并归纳出五种失败形态。

03文章建议的五条防御

  1. 状态分级

    按可重建、需保护、只能快照、不可撤销分类，各定保留期和加密要求，并落到策略上。

  2. 快照密钥分域

    快照加密密钥和沙箱运行时密钥不放在同一个信任域。

  3. 克隆前剥离

    先剔除凭据和 Cookie，克隆后按实例重新注入短时凭证。

  4. 回滚后再验证

    重新校验凭证是否有效、审批是否成立、外部副作用是否发生；不成立就阻断并转人工。回滚本身也要授权。

  5. 状态血缘

    记录快照和克隆的来源、时间、敏感内容、使用范围，删除时级联。

04对 ByClaw 意味着什么

这一节是我们的判断，不是原文内容。

能力我们的规划怎么处理
休眠和快照如果启用凭证不进快照；唤醒后重新注入短时凭证；明确快照的加密、权限和保留期
持久家目录已在使用里面有浏览器和 CLI 登录，要规定保留期和清理责任
批量克隆如果启用克隆前剥离凭证；预热模板不放任何用户状态
回滚规划里不用重启续跑是沿只追加的日志往下走，不把状态退回过去
重启后续跑规划中工具结果未知时由模型先核实；外部动作可能重复，所以建议只有只读类任务自动续跑
