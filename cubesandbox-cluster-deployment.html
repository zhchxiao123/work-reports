03 / HOST KERNEL

没有硬件嵌套虚拟化时，启用 PVM

新节点原内核没有 /dev/kvm、没有暴露 vmx，加载 kvm_intel 返回不支持。CubeSandbox 采用与旧节点相同的 PVM 宿主内核，加载 kvm_pvm 提供运行能力。Firecracker 已按要求卸载，不属于当前部署。

这些步骤改变启动内核。仅对已确认可重启的目标主机执行；已有控制节点不需要为了加节点而重启。本次只重启了新节点。

从官方 kernel-release 发布页取得 DEB 主包及对应 GRUB 配置脚本，或使用本环境已校验的保留材料。不要以 master 最新内核替代本次固定内核而宣称复现。

# root；安装材料先放在 /opt/cube-cluster-node
install -d -m 700 /opt/cube-cluster-node/backups
cp -a /etc/default/grub /opt/cube-cluster-node/backups/grub.before-pvm

dpkg-deb -f /opt/cube-cluster-node/downloads/pvm-kernel-cn.deb \
  Package Version Architecture
dpkg -i /opt/cube-cluster-node/downloads/pvm-kernel-cn.deb
bash /opt/cube-cluster-node/host_grub_config.sh

KVER=6.6.69-opencloudos9.cubesandbox.pvm.host-g0de43d6b3bcd
sed -i "s|^GRUB_DEFAULT=.*|GRUB_DEFAULT=\"Advanced options for Ubuntu>Ubuntu, with Linux $KVER\"|" /etc/default/grub
update-grub
ls -l /boot/vmlinuz-$KVER /boot/initrd.img-$KVER
# 确认启动配置和业务窗口后重启
systemctl reboot

# 重连后
uname -r
modprobe kvm_pvm
printf 'kvm_pvm\n' > /etc/modules-load.d/kvm-pvm.conf
lsmod | grep kvm
ls -l /dev/kvm

04 / STORAGE

为 Cubelet 准备 reflink XFS

cubecow 依赖文件系统的 reflink。新节点系统分区为 ext4，因此创建单独 64 GiB loop XFS 挂载到 /data/cubelet。这是本次 PoC 的布局，不是独立物理数据盘。

# 仅适用于全新目标；任何现有路径都会终止操作
set -eu
[ ! -e /data/cubelet ]
[ ! -e /opt/cube-cluster-node/cubelet.xfs ]
cp -a /etc/fstab /opt/cube-cluster-node/backups/fstab.before-cube
mkdir -p /data/cubelet
truncate -s 64G /opt/cube-cluster-node/cubelet.xfs
mkfs.xfs -m reflink=1 /opt/cube-cluster-node/cubelet.xfs
printf '/opt/cube-cluster-node/cubelet.xfs /data/cubelet xfs loop,defaults 0 0\n' >> /etc/fstab
mount /data/cubelet
findmnt /data/cubelet
xfs_info /data/cubelet
已有控制节点的 /data/cubelet 和 /opt/dsh-cube-verify/cubelet.xfs 必须保留。扩容不需要格式化、卸载或重装控制节点。
05 / CONTROL PLANE

从空主机到第一台完整节点

下面是固定版本的全新控制节点搭建顺序。当前 220 已部署完成，本次扩容没有重新执行控制平面安装。

06 / COMPUTE NODE

复用同版本材料，加入第二台机器

当前控制节点的保留材料位于 /opt/dsh-cube-verify/downloads/。新节点材料位于 /opt/cube-cluster-node/downloads/。通过 SSH 或受控内网传输直接复制到新节点，再比对 SHA-256；不需要把原机 Docker 镜像下载到本地。

# 新节点：先完成前面 PVM、XFS 步骤
export DEBIAN_FRONTEND=noninteractive
apt-get update
apt-get install -y xfsprogs s3fs e2fsprogs util-linux docker.io \
  docker-compose libaio1 libnuma1 uuid-runtime nvme-cli jq
cd /opt/cube-cluster-node
tar -xzf downloads/bundle.tar.gz
cd cube-sandbox-one-click-v0.7.2-amd64
umask 077
cat > .env <<'ENV'
ONE_CLICK_DEPLOY_ROLE=compute
ONE_CLICK_CONTROL_PLANE_IP=[220 内网 IP]
ONE_CLICK_CONTROL_PLANE_CUBEMASTER_ADDR=[220 内网 IP]:8089
ONE_CLICK_CONTROL_PLANE_CUBEOPS_ADDR=[220 内网 IP]:3010
CUBE_SANDBOX_NODE_IP=[118 内网 IP]
CUBE_PVM_ENABLE=1
CUBE_SANDBOX_MINIO_ENABLED=0
ONE_CLICK_ENABLE_TENCENT_DOCKER_MIRROR=0
ENV

在本机通过 SSH 管道传递控制节点的 S3 参数，不把凭据输出到终端日志：

# 在操作电脑执行；两端均已配置 SSH 公钥认证
set -o pipefail
ssh root@[220 公网 IP] \
  'grep "^CUBE_S3_" /usr/local/services/cubetoolbox/.one-click.env' \
| ssh root@[118 公网 IP] \
  'umask 077; cat >> /opt/cube-cluster-node/cube-sandbox-one-click-v0.7.2-amd64/.env'

# 新节点执行
cd /opt/cube-cluster-node/cube-sandbox-one-click-v0.7.2-amd64
chmod 600 .env
./install-compute.sh
./smoke.sh
systemctl is-active cube-sandbox-compute.target \
  cube-sandbox-cubelet.service cube-sandbox-cube-egress.service
v0.7.2 的 toggle 快照读取第一条同名赋值。先 cp env.example，再在末尾追加 CUBE_PVM_ENABLE=1，会保留前面的 0 并触发 PVM 检查失败。使用唯一赋值或原位修改，不要绕过检查。

Cubelet 启动后自动向 CubeOps 注册，没有单独的 node add 命令。此时检查 220 和 118 都为 HEALTHY=true、SCHEDULING_DISABLED=false、RUNNING。cube-egress 应正常启动，并取得与原模板一致的 CA；不能仅凭 Cubelet 进程存在宣布完成。

08 / PLACEMENT

当前调度配置与 DSH 的放置关系

解析模板和资源→健康与约束预筛→CPU / 内存 / 模板 / 并发过滤→候选节点选择

当前服务器的实际配置如下，未启用资源评分，最终候选数为 1：

scheduler:
  priority_select_num: 1
  metric_update_timeout: 300s
  local_metric_update_timeout: 300s
  filter:
    enable_filters:
      - cpu
      - mem
      - template_locality
      - realtime_create_num

过滤后取候选列表中的首个可用节点。一次普通 SDK 创建落到 118 证明新节点参与调度，但不证明负载均衡，也不保证每次都落到 118。若要固定工具 B 主机，应在创建层设置明确的节点约束；不能用全局隔离旧节点的方式代替业务放置。

可选后续：启用资源评分（当前未应用）

按官方 v0.7.2 文档，合并下面片段到现有 scheduler 段，保留原过滤器；备份配置，在合适窗口重启 CubeMaster。评分指标是资源配额使用、沙箱数及创建并发，并非简单地读取 top 中的 CPU 百分比。

# 这是建议配置，当前服务器没有应用
priority_select_num: 2
score:
  enable_scorers: [real_time_weighted_average]
  resource_weights:
    mvm_num: 2
    local_create_num: 3
    quota_cpu_usage: 1
    quota_mem_usage: 1
  plugin_conf:
    real_time_weighted_average:
      weight: 1.0
      enable_weight_factors:
        - mvm_num
        - local_create_num
        - quota_cpu_usage
        - quota_mem_usage

已有 A/B 绑定继续指向原 sandbox ID；扩容不会搬迁实例。每次工具调用连接既有 B，暂停恢复已在新节点验收。删除重建会产生新实例，需要恢复工作区并刷新 binding；本次没有验收持久卷跨节点迁移。

公开 SDK 没有业务自定义 sandbox ID 参数。使用 metadata 保存 workspace/user 等业务标识，业务层维护稳定名称到实际 ID 的映射；内部同 ID 重建机制主要用于生命周期恢复。

09 / ACCESS

管理页面通过 SSH 转发访问

WebUI 在控制节点监听 12088，公网该端口未连通。当前使用本机 loopback 转发，验证返回 HTTP 200，无需修改云安全组。

# 操作电脑；前台运行，关闭终端即关闭隧道
ssh -N -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -L 127.0.0.1:12088:127.0.0.1:12088 root@[220 公网 IP]

# 另一个终端检查
curl -I http://127.0.0.1:12088/

浏览器打开 http://127.0.0.1:12088/。需要后台隧道时增加 -f；本机端口已占用时可改成 12089。此链接指向读者自己的电脑，并不是本文公开站点提供的管理服务。
