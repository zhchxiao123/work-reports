01 / 原工程报告

结论摘要

一句话：这份材料能拼出一张可信的系统地图——仓库结构、数据模型、API 面、数据库表名候选、配置面——但拼不出一行原始代码。按“理解系统”加权，还原度约 25%；按“可编译源码”口径，0%。

  • 代码逻辑是硬边界：函数体、表达式、控制流从未以文本形式存在于二进制中，strings 无法触及。
  • 验证脚本逐项实测确认：无 .symtab、无 DWARF、无分离调试文件、无 cargo-auditable 数据——没有任何隐藏信息能抬高上述数字。
  • 伪代码（反编译）路线需要二进制本体 + 专业 RE 环境，产物是语义近似的伪代码，仍不是原始源码；本报告不沿该路线展开恢复。

系统结构：Rust workspace 单体

Hatch 不是单一执行器，而是一个把 agent 核心、服务端、daemon、数据库层、定时任务、目标系统、内容运行时、语音、安全与自我改进全部静态打进一个二进制的 workspace 单体——这解释了 443 MB 体积与 336 MB 代码段。核心 crate 按引用频次（≈被日志/错误路径提及的密度）：

crate定位（按命名与符号证据）
hatch_agentAgent 核心：会话循环、工具调度、子代理管理，是全系统重心之一
hatch_server服务端主体：Spaces / artifact 网关等 HTTP 面
hatch_daemon_*daemon 家族：内核、服务群、HTTP 客户端与内容/语音/设备接口
hatch_db_* / hatch_postgres数据层：会话、目标、Spaces、调度、浏览器、执行状态等分库 crate
hatch_cron / hatch_goals / hatch_feed / hatch_ideas / hatch_spaces产品域：定时任务、目标、Feed、Ideas、Spaces
hatch_inference / hatch_metering推理客户端与用量计量
hatch_safety / hatch_alignment_dream_*安全分类与对齐合成等后台管线
hatch_voice_* / hatch_realtime / hatch_chat_transport_*语音通路、实时通道与外部消息通道（WhatsApp / Messenger）

骨架工程已按 hatch-engine/crates/…/src/… 的原始目录形态重建 5,439 个文件节点，可在编辑器中展开对照本节阅读。

  • 数据库 schema（更正）：strings 里的 CREATE TABLE 绝大多数是 SQLite 库自带模板，并非应用 schema。应用使用 drizzle ORM，自有 DDL 以完整文本出现的仅 __drizzle_migrations 一张迁移日志表；表名只能从 SQL 查询片段（FROM / JOIN / INSERT INTO / UPDATE 后的标识符）反推候选，共 33 个候选表名、无列定义。因此数据库 schema 仅为表名候选级，不能据此抄出列名与类型。
  • 配置面：环境变量名（如推理主机名、代理 socket、探针间隔一类 JARVIS_* / HATCH_* 键）、*_enabled 特性开关、默认值字面量均在明处。
  • 行号信息：全文只有 2 处 文件:行:列——行号在二进制里是整数存储、不走字符串，因此连“每个文件多少行”都推不出来。

08 / 原工程报告

外部路线验证：REA 与符号后路

8.1 REA（morluto/rea）

  • REA 是把 Ghidra/Hopper/IDA 等逆向工具编排成 MCP/CLI 的 agent 层（npm 包 rea-agents，MIT）；其 Rust 独门能力是解析 cargo-auditable 嵌入的 .dep-v0 依赖清单。
  • 对 hatch 实测：无 .dep-v0、无 .rustc 段，auditable 签名为 0——该构建未带 cargo-auditable 数据，REA 的 Rust 提取器会返回空。
  • “按版本号去 crates.io 拉依赖源码”同样受阻：带确切版本号的依赖路径仅 1 条（tree-sitter 0.25.10），其余路径的版本已被重映射剥除——瓶颈在依赖识别，不在拉取。
  • 结论：REA 改变不了本报告的还原账；它的适用场景是分析自有二进制或学习 agent 驱动的逆向流程。

8.2 伪代码路线的前提与代价

  • 假设二进制在手 + 正经 RE 工作站：函数边界与调用图可恢复，伪代码语义等价约 30–50%；Rust 的泛型与内联会让质量低于 C 程序。
  • 永久丢失：注释、原始命名、宏展开前结构、模块组织方式——伪代码永远不是原始源码。
  • 量级参考：443 MB、.text 336 MB 的 stripped Rust 二进制，全量反编译在专业环境也是以天计的工作。
09 / 原工程报告

建议的后续用法

  1. 把骨架工程当作地图使用：按 crate → 文件 → 符号三层对照本报告第 4、5 节，定位任何子系统在仓库中的位置。
  2. 优先利用高还原维度：配置键清单、API 路由清单可直接用于接口对照与故障排查；数据库方面仅有 33 个候选表名可作核对线索，无列定义可用。
  3. 深挖单个 crate：用 ripgrep 对 strings 原文按 crate 名过滤展开（附录命令），比通读全量文本高效一个量级。
  4. 版本对齐：若需字节级结论（偏移、哈希），须对当前版 a133d60349d 重新提取 strings；结构性结论可直接沿用。
