01

定位：会话事件的底座

它能承载 conversation，但不是完整 Agent 会话系统。核心是持久、可寻址、有序、可回放的 HTTP 数据流。

应用自己定义

conversationId、消息结构、工具事件、权限和完成条件。Stream 只是承载这些数据的底层。

协议提供

创建、追加、读取、关闭与删除；按 offset 补读历史并追踪实时数据。

实现选择

仓库有多语言客户端、Node 参考服务器与 Caddy 插件。Node 参考服务定位开发测试，不能据此承诺生产容量。

02

断线续读：执行与观看解耦

连接断开后，客户端从已确认的 offset 继续读取。应用不应因为浏览器刷新就重新执行昂贵任务。

① 生产者追加

服务端将模型输出、工具进度等追加到流。字节位置不可修改；内容格式由 Content-Type 与上层约定。

② 客户端保存进度

读取并处理数据后保存续读位置。恢复时补读未消费部分，赶上后转 live tail。

③ 实时追踪

协议支持 long-poll 和 SSE。流本身保留数据，不再只依赖某条 WebSocket / SSE 连接存活。

offset 是 opaque token，不是应用自行递增的消息 ID。conversationId、turnId、eventId 与 offset 是不同概念，建议事件记录保留业务标识，而续读使用协议 offset。

官方依据：README · 协议规范

补充：普通读取与订阅交付是两条模型。

普通 GET/SSE 保存客户端 offset；协议另定义 subscription ACK。固定版本 Caddy 已有 webhook callback ACK，但控制路由与内存消费状态和完整 pull-wake 规范存在差距，尚未验证跨重启恢复。查看本次源码核对与 JetStream 比较。

03

写入去重与 fencing

协议定义 Producer-Id、Producer-Epoch 与 Producer-Seq，限制重试重复和旧生产者写入。

Producer-Id

标识逻辑生产者。重试同一写入需要保留对应身份与序列，而不是每次生成新 ID。

Epoch

重启使用更高 epoch；服务器拒绝旧 epoch。epoch 的分配与 Worker owner 切换需要上层协调。

Sequence

同一 epoch 内递增的序号；服务端检查重复和缺口。三个 producer headers 必须一起提供。

流写入幂等 ≠ 工具副作用幂等。 已发出的邮件或成功执行的 shell 不会因为去重 stream append 而撤销或变成 exactly-once。事件可见性与外部操作结果仍需核对。

04

放入 DSH 多实例架构

这是拟议接入方式：API 负责身份与任务，owner Worker 执行，独立事件流负责客户端同步。尚未实现适配。

任务路由

API 根据 binding owner 调度 DSH。Durable Streams 不分配 DSH 实例、不管理运行 Agent，也不自动实现双 owner 防护。

事件发布

DSH adapter 规范化事件后追加：conversationId / turnId / eventId / type / payload。避免公开内部推理、凭据或不必要工具敏感输出。

客户端订阅

鉴权后读取会话流，断线续读。任务崩溃时显示明确状态，不能因流有历史就假设执行已恢复。

数据库与流如何保持一致？

若平台任务表是权威状态，建议用 transactional outbox：任务状态与待发布事件在同一数据库事务提交，再由发布器幂等追加流。Stream append 不会自动与我们的 SQLite / PostgreSQL 事务原子提交。

也可让流成为特定事件的权威记录，但要明确重建投影、版本、权限、保留和业务完成语义。这是设计选择，不是协议自动完成的功能。

05

和 Pi Durable、Temporal、OCE 的关系

分别管理事件传输、Agent 状态、工作流与部署。可以组合，但每层的权威记录与重试责任要明确。

系统主要负责不自动负责
Durable Streams事件保存、offset 续读、实时分发模型循环、任务调度、沙箱恢复

OCE部署、身份、版本与治理替任意 DSH 提供在途任务恢复

06

保留、授权与第一轮验证

协议的数据寿命与服务部署方式决定恢复范围；持久不等于永久。

保留策略

TTL、绝对到期和 retention 都可能影响历史；旧 offset 对应数据不再可读时，要有 snapshot / archive / reset 恢复策略。

身份与访问

URL 是资源地址，不是默认访问许可。会话订阅、追加、fork、删除要受用户 ACL 控制，CDN 缓存与鉴权必须一起设计。

实验路线

测试页面刷新、多设备不同 offset、生产者重试、旧 epoch 拒绝、DSH 崩溃和 retention 边界；核对是否重复展示或误重跑工具。
