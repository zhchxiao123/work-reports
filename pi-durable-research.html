01

定位：库，不是独立集群服务

@earendil-works/pi-durable 在 Pi 中提供持久 conversation / task / document runtime。读取的 package.json 为 1.2.0，README 明确标记 Experimental。

依赖

pi-ai 提供模型访问，Chord 提供文档状态。package exports 包括 tools、env、JSONL / SQLite 等存储适配。

核心单位

一个 Harness 打开一份 Session storage，Session 内多个 conversation，各自有 Agent 配置与 entries。

不是 Temporal

不需要单独 Temporal Server；但也没有自动带来分布式队列、跨进程锁或集群接管。

02

原子提交：状态先落盘，再对外可见

entries 是不可变会话记录，documents 是可变 JSON 状态；commit 可一起创建 tasks、追加 entries 和更新 documents。

Conversation

转录记录与 provider identity；fork 看父会话到指定 entry 的历史，之后独立继续。

Documents

pi.agent、pi.live、pi.inbox、pi.usage 等；业务也可定义 typed document，连同 entries 原子更新。

流式视图

watchEvents 从 commit 派生事件与 deltas；落后过多时重新给 snapshot，不等于持续裸 token 流就是事实来源。

03

崩溃后工具如何处理

Intent 先提交再执行。恢复时能否重新执行取决于 replay 策略，不是所有工具一律重跑。

安全重放

声明 replay: safe 的工具允许重启后重跑；实现者要保证幂等。requestId 解决重复提交，不自动解决远程副作用重复。

非安全调用

崩溃中断的非 replay-safe 调用产生 interrupted 错误结果，保留已提交输出。模型需要基于错误判断，而非默认悄悄再执行。

Task checkpoint

任务按 phase 与 checkpoint 保存进展；重启把 running 改回 pending，waiting 保持等待。不是内存 / OS 进程快照。

04

任务归属、取消与执行环境

模型 generation 拥有 tool tasks；工具可以拥有子会话或子任务。取消和空闲判定沿归属图传播。

Foreground / background

前台子工作随 owner abort 或失败停止，父工作等待它结束；background task 是边界，可独立于父取消存活。

取消不是断开 UI

取消 wait 只取消等待，不取消任务；abort 会处理 queued inputs 和任务树。任务代码忽略 abort signal 会延迟关闭。

环境按调用解析

env(conversationId, read) 从已提交文档查对应执行环境。示例 29 按会话绑定目录；目录并非真实安全沙箱，容器 / Cube 适配需应用自己实现。

05

存储边界决定多实例方案

README 明确：同一 storage 一次由一个进程拥有，没有跨进程锁。不能让两个 DSH Worker 同时打开同一份存储来实现负载均衡。

Memory

仅内存，不持久。适合受控例子，不能作为生产恢复证明。

SQLite / JSONL

SQLite WAL synchronous NORMAL 的最新提交可能在宿主或掉电故障时丢失；JSONL 可 fsync，且历史也驻内存。进程崩溃与机器故障要分开验证。

Cloudflare DO

有 Durable Object SQLite adapter；这不是自动支持任意 Kubernetes 多进程共享数据库。宿主的单 owner 与路由仍要设计。

对 DSH：优先借鉴 commit / replay / ownership 契约。若采用这套 Harness，属于模型循环与状态体系的深层整合，不是给现有 DSH 加一层负载均衡配置即可。

06

研究实验与风险

先做同一 owner 重启恢复，再做 owner 迁移；不把多进程并写混进第一个验收。

实验 1

SQLite 接纳 requestId、执行受控模型与工具，杀进程后 reopen + resume，检查提交历史与结果。

实验 2

分别测试 replay-safe / unsafe 工具、父子 abort、后台任务、tool env 丢失与存储异常关闭。

实验 3

旧 owner 完全退出后迁移存储并恢复，验证 fencing 与端点路由；API experimental，需锁版本与做兼容测试。

三项目分工：OCE 管部署与治理；Temporal 管分布式工作流；Pi Durable 管持久 Agent Harness。可以组合，但任务状态与重试不能由多层无协调地重复拥有。
